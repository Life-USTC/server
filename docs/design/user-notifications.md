# 课表与考试主动通知

首版为当前订阅相关教学班、且在个人课表或考试范围内的用户提供站内通知。用户可以开启 QQ 私聊推送。服务端决定收件人、内容、发送时间和取消条件，Bot 投递消息并回传结果。

## 用户行为

| 消息 | 生成条件和内容 |
| --- | --- |
| 考试安排发布 | 已跟踪的考试首次获得可用安排。显示课程、教学班、已公布的时间和考场，链接到详情。 |
| 考试变更 | 比较同一场考试的已确认安排。改期和换考场同时发生时合成一条，显示变更前后值。详情页显示最新安排。 |
| 考试取消 | 来源明确取消，或经过验证的完整快照及其来源约定可以确认取消。保留原安排供回看。 |
| 考试临近 | 有明确开考时间时按固定提前量安排，建议首版为 24 小时。以 Asia/Shanghai 解释校方时间。改期重排待发提醒，取消时撤销。若改期或发布时已进入提醒窗口，由本次变更或发布通知提供信息。 |
| 加课、单节停课、调课和换教室 | 以某一次上课为单位。调课与换教室同时发生时合成一条，显示原安排和新安排。单节停课保留原时段。 |

首次同步建立基线，用户新订阅时可在课表和考试页查看已有安排。重复导入不产生新消息。来源不可用或快照不完整时保留上一次已确认的比较基线。单节课身份或取消语义尚未验证的来源，待确认后再开启相应通知。导入课表完成在操作页面即时反馈。

收件箱按时间倒序展示，支持未读状态和标记已读。QQ 默认关闭，需要已验证的账号绑定。关闭或解绑停止尚未发送的任务，重新开启不补发关闭期间的消息。站内通知照常生成，QQ 投递结果与已读状态独立。普通站内消息可直接创建，例如为关闭 QQ 的用户记录一条停课通知。

## 变更记录与投递

1. 导入器在确认业务差异的写入边界，用同一个 Prisma `$transaction` 保存新安排和持久的待处理事件。事件记录对象、变更类型、前后值、发生时间和变更标识。业务写入或事件写入失败时一起回滚。重复处理同一次导入沿用变更标识，之后再次发生的同样变更使用新的标识。
2. 服务端按对象和收件范围处理已提交的事件。写入站内通知、创建或撤销提醒计划、创建适用的 QQ 任务和标记事件已处理，使用同一事务。对象的连续事件按顺序处理，避免较旧的事件覆盖较新的提醒计划。按事件与收件人约束唯一性，支持失败恢复。
3. 单个发送进程先按索引定期查询到期任务。领取后、调用 Bot 前再次核对当前安排版本、订阅资格、绑定和开关。对已过期的提醒停止投递。记录结果，恢复中断的任务，并限制重试次数。调用 QQ 后进程退出或调用超时时，投递结果可能未知。跨服务可复用同一个投递标识，实际 QQ 送达仍可能重复。

站内项保存收件人、类型、标题和正文、可选对象引用、创建时间、已读时间以及适用的去重标识。QQ 任务保存渠道、计划时间、状态和最近一次结果。临近提醒用到期时间驱动，到点后才生成可见的站内项和适用的 QQ 任务。普通站内项无需创建投递任务。

## PostgreSQL 与 Prisma

现有导入器在事务中处理导入状态，已经区分考试来源不可用和确认空结果。考试有唯一的上游 `jwId`，导入也有删除旧记录的路径。首版在导入确认差异时显式写事件，跨上游标识匹配和单节课识别以验证过的来源语义为前提。 [导入写入](../../src/static-loader/database-writes.ts) · [快照验证](../../src/static-loader/validation.ts) · [Prisma 模型](../../prisma/schema.prisma)

如果一种变更由多个入口写入，并且可通过旧值和新值可靠判断，可以用 PostgreSQL `AFTER` 触发器记录事件。触发器和原写入一起提交。Prisma 7 可用自定义 SQL migration 部署触发器，仓库已有先例。Prisma 查询扩展只能覆盖经过该客户端的调用。 [仓库触发器迁移](../../prisma/migrations/20260915140000_native_prometheus_counters/migration.sql) · [PostgreSQL 触发器](https://www.postgresql.org/docs/current/trigger-definition.html) · [Prisma 自定义迁移](https://www.prisma.io/docs/orm/prisma-migrate/workflows/unsupported-database-features)

需要降低唤醒延迟时，可以在同一事务调用 `NOTIFY`。提交后监听进程收到信号并查表，启动及重连时仍补扫。多个发送进程确有并行领取需求时，可加 `FOR UPDATE SKIP LOCKED` 和领取超时恢复。 [PostgreSQL NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html)

## 首版验收与后续范围

- 同一场考试改期后能查到最新日期，并收到一条含前后时间的通知。旧提醒撤销，重复导入不重复发，事务回滚后没有可消费事件。若旧任务已被领取，发送前的版本检查会使它失效。
- 一次完整更新明确取消某节课时，关闭 QQ 的用户可以收到并标记已读。资料缺失或来源不可用时不会生成取消通知。
- 服务中断后可以补处理已提交的事件。已开启 QQ 的用户可收到私聊，解绑或关闭后尚未发送的任务停止，站内已读状态仍由用户操作。

后续可增加课前提醒、新作业及截止提醒、个人待办提醒，并接入已有第二课堂提醒。更细的偏好和其他渠道在有使用需求时再引入。 [现有第二课堂通知服务](../../src/features/young/server/young-notification-service.ts)
